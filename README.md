# Монитор замечаний «Школа» — установка и запуск

Готовый комплект из трёх файлов:

| Файл | Что это | Куда идёт |
|---|---|---|
| `Code.gs` | Серверная прослойка (Google Apps Script) | в Apps Script вашей таблицы |
| `index.html` | Пульт (сайт) | в репозиторий GitHub Pages |
| `config.js` | Адрес API и токен | туда же, рядом с `index.html` |

> **Важное отличие от обобщённого ТЗ.** В вашей реальной выгрузке столбцы **L** и **M**
> уже заняты фото (`Фото ссылка`, `Фото айди`), а в **K** лежит формула `=IMAGE(...)`.
> Поэтому служебный столбец **ID вынесен в N**, а сервер берёт фото из K → L → M
> (надёжнее всего срабатывает голый ID из **M**). Менять структуру таблицы не нужно — всё учтено в коде.

---

## Шаг 1. Подготовка Google-таблицы

1. Откройте вашу Google-таблицу с листами **«Замечания»**, **«Роль»**, **«Выпадающий список»**.
2. **Столбец C («Помещение»)** → выделите его → меню **Формат → Числа → Обычный**.
   (Это убирает баг, когда код помещения показывается как дата вроде `02.05.1940`. На всякий случай сервер тоже конвертирует дату обратно в число.)
3. **Лист «Роль»** — проверьте, что он заполнен так (роли в столбце A — строго этими словами):

   | A: Роль | B: Пароль |
   |---|---|
   | Подрядчик | `1111` |
   | Брусника | `2026` |

   Наблюдатель в списке не нужен — он работает без пароля. Пароли можно сменить на свои.
4. **(опционально)** Хотите журнал изменений? Создайте лист с названием **«Аудит»** — сервер сам начнёт писать туда строки `время · ID · старый статус · новый статус · роль`. Если листа нет, аудит просто не ведётся.
5. **Фото.** Файлы фотографий должны лежать в Google Drive того же аккаунта, что владеет таблицей (тогда прокси-режим читает их напрямую). Если хотите быстрый режим «прямые превью» (см. Шаг 4), откройте доступ к файлам/папке «**Все, у кого есть ссылка — Просмотр**».

---

## Шаг 2. Развёртывание Apps Script

1. В таблице: **Расширения → Apps Script**.
2. Удалите содержимое файла `Код.gs` и вставьте весь текст из моего **`Code.gs`**. Сохраните (Ctrl/Cmd+S).
3. Задайте секреты: слева **⚙ Настройки проекта → Свойства скрипта → Добавить свойство**. Создайте два:
   - `API_TOKEN` — придумайте длинную случайную строку (например, 32 символа). Запомните её — она же пойдёт в `config.js`.
   - `HMAC_SECRET` — ещё одна длинная случайная строка (для подписи сессий, в `config.js` не нужна).

   > Сгенерировать строку можно где угодно, например выполнив в браузерной консоли:
   > `crypto.randomUUID()+crypto.randomUUID()`
4. **Проверьте чтение и выдайте разрешения.** Сверху выберите функцию **`setupCheck`** → нажмите **▷ Выполнить**. Google попросит разрешения — согласитесь (нужны доступы к Таблицам и Диску). В разделе **Журнал выполнения** должно появиться число прочитанных замечаний.
5. **Разверните как веб-приложение:** кнопка **Развернуть → Новое развёртывание → тип «Веб-приложение»**:
   - *Описание*: любое;
   - **Выполнять от имени: Я (владелец)**;
   - **У кого есть доступ: Все**;
   - **Развернуть**.
6. Скопируйте **URL веб-приложения** — он заканчивается на `/exec`. Это ваш `API_URL`.

> ⚠️ При любом изменении кода `Code.gs` нужно **создать новую версию развёртывания**
> (**Развернуть → Управление развёртываниями → ✏ → Версия: Новая → Развернуть**),
> иначе правки не попадут на боевой URL.

## Шаг 3. Заполнение `config.js`

Откройте `config.js` и подставьте свои значения:

```js
window.CONFIG = {
  API_URL: "https://script.google.com/macros/s/ВАШ_ID/exec",  // из Шага 2.6
  API_TOKEN: "та_же_строка_что_в_Script_Properties",          // из Шага 2.3
  POLL_MS: 60000,
  PHOTO_VIA_PROXY: false
};
```

`PHOTO_VIA_PROXY`:
- `false` — фото грузятся прямыми превью из Drive (быстро). Если файл недоступен по ссылке, Пульт **сам переключится** на прокси для этого фото.
- `true` — всегда через прокси Apps Script (надёжно, работает даже без публичного доступа к файлам, но медленнее и тратит квоты). Рекомендую `false`; переключите на `true`, если превью не открываются.

## Шаг 4. Публикация на GitHub Pages

1. Создайте новый репозиторий на GitHub (можно **приватный** — так токен не будет виден посторонним; GitHub Pages работает и с приватными репозиториями).
2. Загрузите в корень репозитория **`index.html`** и **`config.js`** (кнопка **Add file → Upload files** на сайте GitHub — без терминала).
3. **Settings → Pages → Build and deployment → Source: Deploy from a branch**, ветка **`main`**, папка **`/ (root)`** → **Save**.
4. Через 1–2 минуты вверху появится адрес вида `https://ВАШ_ЛОГИН.github.io/ИМЯ_РЕПО/`. Откройте его.

> Если решите оставить репозиторий публичным — помните: `API_TOKEN` будет виден в `config.js`.
> Для внутреннего инструмента это допустимо (право на запись всё равно защищено серверной
> проверкой роли по паролю). Для приватности — приватный репозиторий.

## Почему раньше не открывалось с телефона

Прототип был обычным файлом `monitor.html` на вашем компьютере. Телефон не имеет доступа
к файлам ПК, поэтому открыть его там было нечем. После публикации на GitHub Pages у сайта
появляется обычный `https`-адрес — он открывается на любом телефоне в любом браузере.
Вёрстка уже адаптивная (тач-зоны ≥ 44px, фильтры спрятаны под кнопку, кнопки во всю ширину,
учтены «безопасные зоны» вырезов, добавлен pull-to-refresh).

## Что уже реализовано (по чек-листу ТЗ)

- Роль по умолчанию «Наблюдатель» без пароля; вход по паролю через сервер (пароли клиенту не передаются).
- Матрица переходов проверяется **на сервере**; запрещённые переходы отклоняются.
- Запись статуса по стабильному `ID` (UUID в столбце N, скрипт дозаполняет пустые).
- Группировка чипсами до 6 уровней (по умолчанию Блок → Помещение), сворачивание групп, счётчики «всего · принято».
- Три масштаба (Список / Карточки / Большие), фильтр по статусу, поиск — работают совместно.
- Фото: распознаются ссылка Drive, голый ID и «уехавшие» в L/M значения; формат-имя-файла даёт «нет фото»; лайтбокс с прокси-фолбэком.
- Баг «помещение как дата» обезврежен (число).
- Автообновление раз в минуту + ручная кнопка + pull-to-refresh, без сброса раскрытых групп и прокрутки; конфликт правок (`expectedStatus`) обрабатывается тостом и подтягиванием свежих данных.
- Состояния загрузки / ошибки / пусто оформлены.

## Возможные проблемы и решения

| Симптом | Причина / решение |
|---|---|
| «Не настроен config.js» | Не подставили `API_URL`/`API_TOKEN`. См. Шаг 3. |
| «BAD_TOKEN» | `API_TOKEN` в `config.js` ≠ значению в Script Properties. |
| Пустой список, но в таблице данные есть | Лист называется не «Замечания», либо забыли создать **новую версию** развёртывания после правок. |
| Вход не проходит с верным паролем | Проверьте лист «Роль»: названия ролей точно `Подрядчик`/`Брусника`, пароль в столбце B. |
| Фото не открываются | Поставьте `PHOTO_VIA_PROXY: true` в `config.js`, либо откройте доступ к файлам Drive «по ссылке». |
| Кнопки статуса не появляются | Вы под «Наблюдателем». Нажмите «сменить роль» и введите пароль. |
